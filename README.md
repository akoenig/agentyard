# Personal Agent Infrastructure

Docker Compose setup for running multiple isolated Hermes agents behind local Caddy TLS.

Shared services:

- Caddy reverse proxy with self-signed TLS from Caddy's internal CA
- Postgres server used by per-agent LiteLLM databases

Per agent:

- One self-contained `agents/<name>/` directory
- One `config/` directory for committed Compose, Caddy, and LiteLLM files
- One `data/` directory for ignored Hermes and LiteLLM runtime state
- One Hermes gateway container
- One LiteLLM proxy container
- One Postgres database for LiteLLM state, virtual keys, spend, and usage logs
- One ChatGPT OAuth token directory, allowing each agent to use its own ChatGPT subscription
- One Hermes data directory mounted at `/opt/data`

Optional frontend:

- OpenWebUI deployment under `frontend/`
- Cloudflare Tunnel for `https://chat.<domain>` without publishing host ports

No agent is included by default. Always create agents with `scripts/create-agent`.

OpenWebUI is optional and is configured separately in `frontend/`. See `frontend/README.md`.

## Architecture

The base stack is defined in `compose.yaml` and contains only shared infrastructure. Each agent owns its Compose, Caddy, and LiteLLM files under `agents/<name>/`.

Example generated agent named `research`:

```text
agents/research/
  config/
    compose.yaml
    caddy.caddy
    litellm.yaml
  data/
    hermes/
    litellm/

Caddy
  -> research-hermes-api.$AGENT_BASE_DOMAIN  -> hermes-research:8642
  -> research-litellm-api.$AGENT_BASE_DOMAIN -> litellm-research:4000

hermes-research -> litellm-research -> ChatGPT subscription for research
```

Each LiteLLM instance uses its own database, for example:

```text
litellm_research
litellm_work
litellm_home
```

## Initial Setup

1. Create the local environment file.

```bash
cp .env.example .env
chmod go-rwx .env*
```

2. Edit `.env` and replace shared infrastructure values.

Shared settings:

- `COMPOSE_PROJECT_NAME`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `AGENT_BASE_DOMAIN`
- `CADDY_BIND_ADDRESS`
- `CADDY_HTTPS_PORT`

LiteLLM and Hermes credentials are agent-specific and are generated by `scripts/create-agent`.

3. Start shared infrastructure.

```bash
docker compose up -d postgres caddy
```

Postgres initializes `data/postgres/` on first start. That directory must be empty before the first successful start. If an initial start failed before Postgres initialized, remove the failed local data directory and retry:

```bash
docker compose down
rm -rf data/postgres
docker compose up -d postgres caddy
```

## Creating An Agent

Create an isolated agent with a lowercase name:

```bash
scripts/create-agent research
```

This creates:

- `agents/research/config/compose.yaml`
- `agents/research/config/caddy.caddy`
- `agents/research/config/litellm.yaml`
- `litellm-research` service with container name `research-litellm`
- `hermes-research` service with container name `research-hermes`
- `agents/research/data/litellm/`
- `agents/research/data/hermes/`
- `.env` entries for `LITELLM_RESEARCH_MASTER_KEY`, `LITELLM_RESEARCH_SALT_KEY`, and `HERMES_RESEARCH_LITELLM_KEY`
- `.env` entry for `HERMES_RESEARCH_API_SERVER_KEY`, used as the bearer token for the Hermes API server
- Postgres database `litellm_research`, if Postgres is running
- Caddy config reload, if Caddy is running

Generated LiteLLM services use `ghcr.io/berriai/litellm-database:main-stable`. This avoids relying on the `docker.litellm.ai` registry endpoint while still using LiteLLM's published database-enabled image.

The generated LiteLLM config reads the master key from `LITELLM_MASTER_KEY` inside the container. The generated Compose file maps the agent-specific host value, for example `LITELLM_RESEARCH_MASTER_KEY`, into that container variable.

Add the generated hostnames to DNS or your local hosts file so they resolve to this machine:

```text
research-litellm-api.$AGENT_BASE_DOMAIN
research-hermes-api.$AGENT_BASE_DOMAIN
```

If Postgres was not running when `scripts/create-agent` ran, create the database manually before starting that agent's LiteLLM:

```bash
docker compose exec postgres createdb -U litellm litellm_research
```

Start that agent's LiteLLM and complete ChatGPT OAuth:

```bash
docker compose -f compose.yaml -f agents/research/config/compose.yaml up -d caddy litellm-research
docker compose -f compose.yaml -f agents/research/config/compose.yaml logs -f litellm-research
```

The ChatGPT auth token for this agent is stored below `agents/research/data/litellm/chatgpt/` and survives container recreation.

Generate the agent's Hermes virtual key after OAuth succeeds:

```bash
scripts/create-agent-key research
```

This writes `HERMES_RESEARCH_LITELLM_KEY` into `.env`.

Start the Hermes agent:

```bash
docker compose -f compose.yaml -f agents/research/config/compose.yaml up -d hermes-research caddy
```

Run Hermes setup for that agent if needed:

```bash
docker compose -f compose.yaml -f agents/research/config/compose.yaml run --rm hermes-research setup
```

Test the Hermes API server:

```bash
curl --insecure "https://research-hermes-api.$AGENT_BASE_DOMAIN/health" \
  -H "Authorization: Bearer $HERMES_RESEARCH_API_SERVER_KEY"
```

Hermes' OpenAI-compatible API server is enabled in the generated Compose file with `API_SERVER_ENABLED=true`, `API_SERVER_HOST=0.0.0.0`, and `API_SERVER_PORT=8642`. The port is only exposed on the internal Docker network and is reached through Caddy.

List configured agents:

```bash
scripts/list-agents
```

Delete an agent and its local runtime data:

```bash
scripts/delete-agent research
```

This stops `hermes-research` and `litellm-research` if Docker is available, removes `agents/research/`, removes the agent-specific `.env` entries, drops the `litellm_research` database if Postgres is running, and reloads Caddy if Caddy is running.

The helper scripts use standard POSIX shell tools. `scripts/create-agent-key` also requires `curl` and `python3` to call LiteLLM and extract the generated key from the JSON response.

## Running Multiple Agents

Because each agent owns its own Compose file, start multiple agents by passing each agent Compose file explicitly:

```bash
docker compose \
  -f compose.yaml \
  -f agents/research/config/compose.yaml \
  -f agents/work/config/compose.yaml \
  up -d
```

This keeps agent changes isolated in `agents/<name>/` and avoids a shared generated Compose file.

## Local Caddy

Caddy is included in Compose and terminates TLS using Caddy's internal certificate authority via `tls internal`.

Published host ports:

- Caddy HTTPS only: `$CADDY_BIND_ADDRESS:${CADDY_HTTPS_PORT:-443}`

No LiteLLM, Hermes, Postgres, or Caddy HTTP port is published to the host. Set `CADDY_BIND_ADDRESS` to a specific interface, such as `127.0.0.1` for local-only access or the host's private IP when a front reverse proxy runs on another machine. Do not set it to `0.0.0.0` unless you intentionally want Caddy HTTPS reachable on every interface.

The root Caddyfile imports all per-agent routes:

```caddyfile
import /etc/caddy/agents/*/config/caddy.caddy
```

The root Compose file mounts `./agents` into Caddy at `/etc/caddy/agents`, so each `agents/<name>/config/caddy.caddy` file is picked up by the import.

The repository includes `agents/_placeholder/config/caddy.caddy` so Caddy has a valid import target before the first real agent is created. Directories beginning with `_` are internal and are ignored by `scripts/list-agents`.

Example generated route for `research`:

```caddyfile
research-litellm-api.<AGENT_BASE_DOMAIN> {
  encode zstd gzip
  tls internal
  reverse_proxy litellm-research:4000
}

research-hermes-api.<AGENT_BASE_DOMAIN> {
  encode zstd gzip
  tls internal
  reverse_proxy hermes-research:8642
}
```

Because `tls internal` uses a local CA, clients need to trust Caddy's root certificate or explicitly allow the self-signed certificate, for example with `curl --insecure` during bootstrap.

Caddy stores its internal CA and certificates under `data/caddy/`.

## Front Reverse Proxy

If another Caddy instance sits in front of this local Caddy, proxy to the local Caddy over HTTPS and preserve the agent hostname. The local Caddy routes by `Host` header, and the upstream TLS SNI must also match the agent hostname when proxying to the local Caddy by IP address.

Recommended: copy the local Caddy root CA certificate from the agent host to the front proxy host:

```text
data/caddy/data/caddy/pki/authorities/local/root.crt
```

Example front Caddy config:

```caddyfile
research-litellm-api.example.com {
  encode zstd gzip

  reverse_proxy https://agent-host:443 {
    header_up Host research-litellm-api.example.com

    transport http {
      tls_server_name research-litellm-api.example.com
      tls_trusted_ca_certs /etc/caddy/certs/agents-root.crt
    }
  }
}

research-hermes-api.example.com {
  encode zstd gzip

  reverse_proxy https://agent-host:443 {
    header_up Host research-hermes-api.example.com

    transport http {
      tls_server_name research-hermes-api.example.com
      tls_trusted_ca_certs /etc/caddy/certs/agents-root.crt
    }
  }
}
```

Less secure fallback for a private, controlled network:

```caddyfile
research-litellm-api.example.com {
  reverse_proxy https://agent-host:443 {
    header_up Host research-litellm-api.example.com

    transport http {
      tls_server_name research-litellm-api.example.com
      tls_insecure_skip_verify
    }
  }
}

research-hermes-api.example.com {
  reverse_proxy https://agent-host:443 {
    header_up Host research-hermes-api.example.com

    transport http {
      tls_server_name research-hermes-api.example.com
      tls_insecure_skip_verify
    }
  }
}
```

## Virtual Keys And Usage

Each Hermes agent gets a LiteLLM virtual key from its own LiteLLM instance. That keeps usage, spend logs, budgets, and key controls isolated per agent.

`scripts/create-agent-key` names the LiteLLM virtual key with `key_alias: <agent>-hermes`, for example `research-hermes`.

Example key metadata generated by `scripts/create-agent-key`:

```json
{
  "owner": "agent:research",
  "type": "hermes-agent"
}
```

## Data

Top-level `data/` contains shared runtime state. Agent-specific runtime state lives under `agents/<name>/data/`. Runtime contents are ignored by git, with empty directories retained via `.gitkeep`.

Important runtime locations:

- `data/caddy/` stores Caddy's local CA and certificates
- `data/postgres/` stores Postgres data
- `agents/<agent>/config/` stores each agent's committed Compose, Caddy, and LiteLLM config
- `agents/<agent>/data/litellm/` stores each agent's ChatGPT OAuth token directory
- `agents/<agent>/data/hermes/` stores each Hermes agent's config, sessions, memories, skills, and logs
